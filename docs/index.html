The problem isn't zero-days

Breaches rarely come from exotic new exploits. They come from old, public, already-patched CVEs sitting in dependency trees nobody audited.

🎯

Known vulns do the damage

Attackers shop the public CVE list. Most exploited vulnerabilities were disclosed — and patched — long before the breach that used them.

🔥

Log4Shell was the warning shot

CVE-2021-44228 scored a perfect 10.0. One logging library buried three layers deep, and half the internet spent a weekend patching.

🧬

100+ deps you never chose

A typical Maven build pulls in a hundred transitive dependencies. You hand-picked maybe five. The other 95+ are attack surface on autopilot.

What it finds

Point it at a pom. Get an X-ray of your supply chain — scored, graded, and mapped to the fixes.

🛰️

Live OSV.dev batch queries

Every package@version goes out in one batched query against the live OSV.dev API. No key, no stale local CVE mirror — if it was published this morning, you'll see it this afternoon.

📊

Risk score 0–100, graded A–F

Severity-weighted scoring turns a CVE pile into one number you can track across builds — and a grade you can put on a dashboard.

🌡️

Severity heatmap

Your whole dependency list shaded by worst severity — a wall of red at the top, cool emerald where you're clean. The attack surface, at a glance.

🧾

Per-dependency CVE table

Every finding mapped back to its package: installed version, CVE id, CVSS severity, and the fixed-in version to upgrade to. No archaeology required.

🚦

CI-friendly --fail-on

Gate the pipeline: --fail-on high exits non-zero the moment a high-or-worse finding appears. Levels: critical | high | medium | low.

🪶

Zero dependencies, Java 17+

Plain javac, the stdlib HTTP client, stdlib XML parsing. Nothing to audit in the auditor.

How it works

Pure JDK. No Maven, no Gradle, no dependencies.

parse pom

java -jar vulnlens.jar pom.xml — resolves declared and transitive dependencies down to exact versions from the Maven model.

batch-query OSV.dev

One POST carries every package@version to the live OSV.dev API. A single round trip covers the whole tree.

score & map

Findings group by dependency, CVSS weights roll up into a 0–100 score and an A–F grade, severities paint the heatmap.

ship the report

Self-contained HTML you can open anywhere, machine-readable JSON for CI, or plain text for the terminal purist.

Run it

Java 17+, one jar, no install. Flags: --format html|json|text, --output, --fail-on critical|high|medium|low, --no-color, --timeout, --quiet.

# build from source (plain javac — no build tool needed)
./build.sh

# scan a project
java -jar build/vulnlens.jar path/to/pom.xml

# machine-readable output, and fail the build on high-or-worse
java -jar build/vulnlens.jar path/to/pom.xml --format json
java -jar build/vulnlens.jar path/to/pom.xml --fail-on high
